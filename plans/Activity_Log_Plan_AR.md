# خطة تنفيذ نظام سجل النشاطات (Activity Log System)

## نظرة عامة
الهدف هو إنشاء نظام مراقبة مخصص للمشرف العام (`admin00`) يسمح بمتابعة كافة التحديثات التي يقوم بها المشايخ في النظام بشكل يومي. سيتم تسجيل عمليات الإضافة، التعديل، والحذف للطلاب والحصص والتقارير في سجل مركزي يمكن استعراضه وتصفيته.

## هيكلة قاعدة البيانات (Database Structure)

سيتم إنشاء عقدة جديدة في قاعدة بيانات Firebase Realtime باسم `activity_logs`.
هيكلة السجل الواحد ستكون كالتالي:

```json
{
  "logs": {
    "$logId": {
      "action": "ADD_STUDENT" | "UPDATE_STUDENT" | "ADD_SESSION" | "DELETE_SESSION" | "SAVE_REPORT" | "DELETE_REPORT",
      "actorId": "uid_of_sheikh",
      "actorName": "اسم الشيخ",
      "targetId": "id_of_student_or_session",
      "targetName": "اسم الطالب (إن وجد)",
      "details": "تفاصيل إضافية (مثلاً: تم تسجيل 5 صفحات)",
      "timestamp": 1234567890 (Server Timestamp),
      "groupName": "اسم الفوج"
    }
  }
}
```

## التغييرات المقترحة (Proposed Changes)

### 1. قواعد الأمان (`database.rules.json`)
- السماح للمشايخ (`sheikh`) بالكتابة في `activity_logs` (الإضافة فقط).
- السماح للإدارة (`management`) و `super_admin` بالقراءة.

### 2. واجهة المستخدم (User Interface)
- إنشاء صفحة جديدة: `src/app/management/logs/page.tsx`
- **المميزات:**
  - عرض جدول زمني للنشاطات مرتبة من الأحدث للأقدم.
  - **فلاتر تصفية:**
    - حسب الشيخ (Actor).
    - حسب نوع النشاط (إضافة، تعديل، حذف).
    - حسب التاريخ.
  - **تصميم بصري:** استخدام ألوان مميزة لكل نوع عملية (أخضر للإضافة، أزرق للتعديل، أحمر للحذف).

### 3. المنطق البرمجي (`src/context/StudentContext.tsx`)
سيتم إنشاء دالة مساعدة داخل الـ Context أو في ملف منفصل `src/lib/logger.ts` باسم `logActivity` واقحامها في الدوال التالية:

| الدالة | نوع النشاط | التفاصيل المسجلة |
|Text | Log Type | Details |
|---|---|---|
| `addStudent` | `Create` | "تم إضافة طالب جديد: [الاسم]" |
| `updateStudent` | `Update` | "تم تعديل بيانات الطالب: [الاسم]" |
| `deleteStudent` | `Delete` | "تم حذف الطالب: [الاسم]" |
| `addDailySession` | `Create` | "تم تسجيل حصة للطالب: [الاسم]" |
| `deleteDailySession` | `Delete` | "تم حذف حصة للطالب: [الاسم]" |
| `saveDailyReport` | `Create/Update` | "تم حفظ التقرير اليومي" |

## خطة التحقق (Verification Plan)

### التحقق اليدوي
1. الدخول بحساب شيخ (مثلاً `admin1`).
2. إضافة طالب جديد -> التحقق من ظهور النشاط في صفحة `admin00`.
3. تسجيل حصة -> التحقق من الظهور.
4. الدخول بحساب `admin00` والتأكد من إمكانية رؤية سجل النشاطات واستخدام الفلاتر.

### التحقق الآلي
- يمكن كتابة اختبار وحدة (Unit Test) بسيط لدالة `logActivity` للتأكد من أنها ترسل البيانات الصحيحة لـ Firebase (إذا كانت البيئة تسمح بذلك)، ولكن الاعتماد الأساسي سيكون على التحقق اليدوي نظرًا لطبيعة المشروع (Frontend + Firebase).
